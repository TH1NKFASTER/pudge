## Global Constraints

- Главный способ получения контента — из Pudge на Mac. Прямой torrent-клиент iPhone не входит в обязательный выпуск.
- Аудиокниги без синхронного текста — завершённый первый продуктовый этап. Для его запуска не нужны Jiten, AniList, AI, EPUB-читалка или видеоплеер.
- Первое сопряжение: «Настройки → Расширенные → iPhone» на Mac показывает QR; «Подключить Mac» в iPhone открывает сканер. В штатном сценарии не требуется вводить IP, порт, ключ или копировать ссылку.
- Визуал Pudge сохраняется: палитра, карточки, обложки, состояния слов, оформление словаря. Компоновка адаптируется к пальцам и маленькому экрану.
- Из интерфейса всегда понятно размещение конкретных частей произведения, их объём, доступность источника и действие переноса.
- Ни одна автоматическая очистка не удаляет единственную подтверждённую копию, пользовательский оригинал, закреплённое содержимое или несинхронизированные изменения.
- Перенос на Mac считается завершённым после проверки данных и устойчивой регистрации на Mac. Полученный HTTP-ответ о загрузке отдельных байтов не является подтверждением сохранности всего объекта.
- Jiten — единственный учебный провайдер первого выпуска. Интерфейс адаптера допускает jpdb позднее; существующий jpdb на Mac не ломать и автоматически не переключать.
- Ревью и добавление слов — разные действия. Просмотр определения не отправляет ответ в SRS.
- Исправление истории Jiten — обязательное требование полного объёма, но зависит от подтверждённых возможностей внешнего сервиса. Без них запрещено выдавать локальную пересборку за исправленную удалённую историю.
- Никаких пробных ревью, удаления карточек или массового импорта в основной аккаунт. Контрактные проверки — на тестовых данных и отдельном тестовом аккаунте после его предоставления.
- Не считать транспортный timeout отказом операции. Не повторять неоднозначную мутацию с новым идентификатором.
- Перед каждым выдаваемым патчем запускать максимально полный технически доступный набор тестов; отдельно указывать недоступные проверки. Не объявлять iOS-сборку проверенной без Xcode.
- Не создавать commits, push, релиз или публикацию без отдельного указания пользователя. Изменения держать изолированно от его незавершённой работы.
- Начальный deployment target: iOS 18.0 как предлагаемое решение для реализации; использовать SDK установленного стабильного Xcode. Новые фоновые API — только по availability, без зависимости базовых сценариев от них.
- Первичная поставка — проект и сборка для личного тестирования; signing team/bundle identifier задаются пользовательской конфигурацией и не выдумываются.

## 1. Решения, которые исполнитель не должен менять молча

### 1.1. Приоритеты выпуска

**P0 — сначала:** QR-сопряжение, каталог аудиокниг с Mac, скачивание и безопасное освобождение места, нативное фоновое аудио, главы/закладки/таймер, точная позиция и продолжение прослушивания на другом устройстве. Реализовать и передать этот этап до ожидания решений по Jiten. Ранний интерфейс может иметь разделы «Аудиокниги», «Загрузки», «Настройки»; не показывать неработающие вкладки других функций.

**Обязательный объём:** Mac ↔ iPhone, ясное размещение и память, ранобэ/манга/аудио, видео с интерактивными субтитрами, Jiten-определения/добавление/ревью, устойчивый журнал, безопасная синхронизация, документированный путь исправления истории.

**Следующий объём:** завершение остальных функций Pudge — оценки, планирование, франшизы, статистика, помощник, управление тяжёлой подготовкой на Mac.

**Позже:** прямое получение релизов на iPhone, локальная генерация аудиокниг, массовое OCR и выравнивание. Нельзя задерживать работающую передачу с Mac ради них.

### 1.2. Состояние размещения

Не использовать единственный enum для всей книги. Отдельно хранить сведения по каждому ресурсу: текст, изображения, аудио, видео, субтитры, токены, OCR, выравнивание.

| Признак | Значения / смысл |
|---|---|
| Копия iPhone | Нет / частично / проверена / повреждена |
| Копия Mac | Нет / проверена на указанной версии / сведения устарели |
| Доступность Mac | Доступен / недоступен / сопряжение отозвано |
| Передача | Очередь / передача / проверка / сохранено / ошибка / приостановлено |
| Защита | Закреплено / текущая сессия / единственный оригинал / перенос незавершён |

Тексты карточки: **«На iPhone»**, **«На Mac»**, **«На обоих»**. При сомнении — **«Копия на Mac не проверена»**, а не уверенное «На обоих». Подпись **«Mac сейчас недоступен»** не меняет сведения о последней известной копии.

Основные действия: **«Скачать на iPhone»**, **«Сохранить на Mac»**, **«Освободить место на iPhone»**, **«Закрепить»**, **«Управлять файлами»**. В нижней панели показывать компоненты и размеры: например, «Текст — на обоих, 4 МБ; аудио — на Mac, 620 МБ».

### 1.3. Правила очистки

Первоначально лимит управляемых загрузок не задан, автоматическая очистка выключена. Пользователь выбирает лимит и включает её на экране памяти; исходники, импортированные на телефон, всегда защищены до проверенного архива на Mac.

Резерв свободного диска для расчёта новых загрузок: `min(5 GiB, max(2 GiB, 5% totalCapacity))`. Это предлагаемая продуктовая настройка, не требование iOS. При дефиците резервов уменьшить план загрузки или предложить освобождение; не стирать защищённое. Если даже резерв недостижим, сообщить об этом и не запускать новую большую передачу.

Оценивать пиковое место: временные части + итоговый файл + необходимая распаковка. Общие ресурсы считать один раз. Очередь очистки: неполные заброшенные временные файлы → проверенные дубликаты завершённых произведений → прочие незакреплённые дубликаты по давности использования. Текущее чтение/воспроизведение и активная передача исключаются.

«Сгрузить обратно» не пересылает гигабайты повторно, если на Mac уже подтверждён тот же ресурс. Сначала синхронизируются изменения, проверяется/закрепляется копия Mac, затем удаляется локальный ресурс. Если ресурс уникален для телефона, сначала выполняется полноценная передача на Mac.

В общем случае аппаратный отказ Mac после переноса нельзя исключить протоколом. Гарантия приложения — не удалять последнюю известную исправную копию собственными действиями и не игнорировать выявленные сбои.

### 1.4. Jiten: граница реально подтверждённых возможностей

В исходниках Pudge (`pudge/review_providers.py`) уже есть:

- `GET /api/srs/study-batch`;
- `GET /api/srs/review-history/{wordId}/{readingIndex}`;
- `POST /api/srs/review` с `clientRequestId`, оценкой и длительностью;
- `POST /api/srs/undo-review` с идентификатором слова/чтения;
- отдельный `ReviewOutcomeUnknown`;
- замечание, что история не возвращает `ClientRequestId`, а серверный кеш идемпотентности в изученной ревизии записывается после commit.

Это свидетельства о текущей интеграции Pudge, **не подтверждение сегодняшнего контракта сервера Jiten**. Изученная Pudge ревизия: `216df6378db619fc0b803f5695dc925c0311ee84`. Официальное руководство Jiten сообщает, что API не версионирован и может меняться. Схему Swagger в этой сессии получить не удалось; актуальная поддержка backdating, атомарного исправления и адресной отмены не подтверждена.

Поэтому T01 — обязательная проверка, а T14 — явная зависимость полного исправления истории. Наличие обычного undo не доказывает возможность безопасно откатить старый ответ после более нового на другом устройстве.

### 1.5. Модель правильной истории

Сохранять три разных слоя:

1. **Наблюдения пользователя:** неизменяемые события ответов на устройствах.
2. **Исправления:** отдельные события, указывающие, какой ответ отменён/изменён и почему; оригинал сохраняется.
3. **Подтверждённая история Jiten:** снимки и идентификаторы реально принятых удалённых операций.

Порядок учитывает причинность (`previousEventId`, ревизия), порядковый номер устройства и оценку времени с погрешностью. UUID или часы телефона сами по себе не доказывают реальный порядок независимых событий. При неоднозначности не угадывать порядок молча.

Одинаковый `eventId` — повтор доставки. Два разных ответа одному слову — два события, даже с одинаковой оценкой и близким временем. Просмотр определения не превращается в повторение; если ответ дан после подсказки, сохранить этот факт и показать отдельный учебный режим, не выдавая его за чистую проверку памяти.

Пересборка локального журнала всегда доступна. Пересборка удалённой истории должна сохранять реальные времена, чужие ответы, параметры планировщика и проверять конкурентные изменения. Цепочка «undo несколько раз → отправить оценки заново сейчас» запрещена: она может изменить смысл истории и затереть более поздние ответы.

**Режим до появления сильного API:** один отправитель Pudge на Mac; iPhone устойчиво сохраняет действия и получает подтверждения через Mac. Без доступного координатора показывает «Сохранено на iPhone, ожидает синхронизации». Если сервис не принимает исходное время, устаревший офлайн-ответ не отправляется как свежий без явно выбранной допустимой семантики: остаётся локальной тренировкой/требует согласования. Это ограниченный режим, не полное выполнение пункта пользователя о пересборке.

**Целевой режим:** Jiten принимает устойчивые идентификаторы, исходное время, ожидаемую ревизию и атомарную адресную коррекцию с пересчётом. Тогда iPhone работает с сервисом независимо от Mac, а порядок и повторы контролируются сервером. Реализация может использовать уже имеющийся подходящий API после проверки либо потребовать изменений самого Jiten; сторонний клиент не может гарантировать это односторонне.

### 1.6. Интерактивные субтитры

Видео проигрывает AVPlayer. Учебные субтитры — отдельный интерактивный слой с репликами и токенами, подготовленными Mac или полученными через Jiten. Это не перенос Lua-плагина mpv.

Нажатие на слово фиксирует `(assetId, cueId, tokenId, wordId, readingIndex)`, ставит видео на паузу и открывает нижнюю панель: написание, чтение, определение, состояние карточки, **«Добавить»**, **«Повторить»**. Повторение раскрывает карточку и допустимые Jiten-оценки. Смена реплики не меняет выбранное слово в открытой панели.

Чтобы палец попадал в мелкий текст, предусмотреть увеличенную текущую реплику над панелью и ленту недавних реплик. Фуригана принадлежит области нажатия слова. Для неизвестного разбора оставить выделение текста/выбор словарного совпадения; не отправлять review для предположительного ID.

В PiP доступен обычный просмотр с поддержанным видом субтитров; учебная панель работает в основном приложении. Это ограничение интерфейса, не отказ от интерактивных субтитров внутри Pudge.

`accountId` не должен равняться хешу ключа API. Если Jiten не предоставляет стабильную идентичность, создать локальную идентичность подключения и проводить явную проверяемую перепривязку при смене ключа; не объединять очереди автоматически.

### 2.1. Уточнение процесса аудиокниг — обязательный контракт P0

#### Первое подключение

1. Mac: открыть «Настройки → Расширенные → iPhone». При первом использовании включить «Подключение iPhone»; после этого в видимой секции автоматически появляется локально сформированный QR. Отдельное повторное нажатие «Сгенерировать» не нужно.
2. QR содержит версию протокола, идентичность Mac/отпечаток его ключа, адреса подключения и одноразовое приглашение на 5 минут. Не содержит Jiten-ключ, долговечный токен устройства или пользовательские пути. Не использовать внешний сервис генерации QR.
3. iPhone: «Подключить Mac» → системный запрос камеры при необходимости → навести камеру приложения на QR → подключение. На первом экране кратко указать, что устройства должны быть в доступной друг другу сети; обычный путь — одна домашняя Wi-Fi/LAN. Наличие Ethernet у Mac не должно мешать.
4. Проверить приглашение и идентичность сервера; выдать отдельный credential телефона, сохранить в Keychain, отметить успешное сопряжение на обоих устройствах. На телефоне сразу открыть каталог аудиокниг. Не заставлять пользователя отдельно вводить аккаунт Pudge.
5. При следующем запуске использовать сохранённое сопряжение. Изменение IP и сон Mac не требуют нового QR. Отзыв доступа — отдельное состояние с предложением подключиться заново.

QR обновляется после истечения/использования, пока секция открыта, с видимой индикацией срока. После успеха показать имя телефона и кнопку «Подключить ещё», а не бесконечно создавать приглашения. Закрытие секции прекращает обновление и отзывает неиспользованное приглашение; уже сопряжённый телефон остаётся подключённым. Активный обмен сопряжения завершается по зафиксированному приглашению, обновление картинки не должно обрывать его.

Обязателен встроенный сканер Pudge. Открытие через штатную Камеру iOS — удобное дополнение при наличии проверенного механизма ссылок; не обещать его без настройки и испытания. Если камера запрещена, есть «Вставить приглашение» как запасной путь. При отсутствии приложения у пользователя должна быть отдельная инструкция установки: QR сам приложение не устанавливает.

#### Скачать и слушать

1. В каталоге отображается библиотека Mac с карточками, томами, обложками, длительностью, последним местом и размещением.
2. «Скачать на iPhone» проверяет место и сохраняет аудио, карту частей, главы, обложку и необходимые метаданные. Статус «Доступно без сети» появляется только для полностью проверенного комплекта. Для P0 скачивается целая выбранная аудиокнига; пофайловая частичная загрузка может быть внутренней стадией, но не выглядит как полная готовность.
3. После скачивания локальное воспроизведение имеет приоритет. Mac можно выключить. Потеря сети не влияет на уже открытое локальное аудио.
4. Прямое прослушивание с Mac до скачивания — необязательная последующая возможность. Если оно добавлено, интерфейс пишет «Слушать с Mac» и не обещает автономность. Не подменять им обязательный сценарий загрузки.
5. Пауза, главы, ±15 секунд, скорость, закладки, таймер сна, наушники и экран блокировки работают через один аудиосервис. Межфайловый переход сохраняет скорость, паузу и оставшийся таймер.

Подготовка аудиоформатов входит в P0 и не ждёт видеозадачи T19. Проверить реальные M4B, MP3, Opus и FLAC из поддерживаемого Mac-набора. Если конкретный контейнер/кодек не работает в выбранном нативном плеере, Mac готовит совместимый вариант, сохраняя оригинал, главы и карту времени. Несовместимый исходник не должен выглядеть успешно скачанным, но немым. Порядок частей берётся из проверенной карты книги, а не пересортировывается по именам после скачивания.

#### Что синхронизируется

| Данные | Правило |
|---|---|
| Позиция и глава | Общие для конкретной редакции/карты времени; история переходов сохраняется |
| Закладки, названия и удаления | Синхронизируются по устойчивым ID с tombstones |
| Завершено / начать заново | Явные события; не вычислять из максимальной позиции |
| Файлы и размещение | Через manifests/receipts, не как часть события прогресса |
| Скорость | Локальная настройка устройства; не менять текущую скорость неожиданно по сообщению с другого устройства |
| Таймер сна и состояние play/pause | Локальны для текущей сессии; не синхронизировать как обычный прогресс |
| Команда «Продолжить здесь» | Отдельная операция передачи прослушивания с подтверждением, не удалённый автозапуск по любому sync |
| История времени | События сессий сохраняются с P0; общий экран статистики появляется позднее |

#### Координаты и частота сохранения

Новый `AudioCheckpoint`: `checkpointId`, `assetId`, `editionId`, `timelineRevision`, `playbackSessionId`, `deviceId`, `sequence`, `baseProgressRevision`, `positionMs`, `partId`, `partPositionMs`, `reason`, `observedAt`. Для состояния завершения — отдельное явное событие. `positionMs` — время аудио на канонической шкале книги, не прошедшее реальное время и не процент.

Карта `AudioTimeline` задаёт устойчивые IDs частей, их порядок, длительность и смещения. Для преобразованного варианта нужна проверенная привязка к исходной шкале; encoder delay/gaps не должны незаметно сдвигать место. При несовместимой редакции автоматически переносить позицию запрещено: предложить выбор соответствия.

Сохранять checkpoint локально не реже одного раза за 5 секунд активного воспроизведения через callbacks плеера и немедленно по pause/seek/chapter-change/finish/interruption/background transition. События final checkpoint не теряются при объединении промежуточных обновлений. Целевая потеря позиции при аварийном завершении — не более 5 секунд нормально исполнявшегося воспроизведения; длительную заморозку/потерю питания измерять отдельно, не гарантировать невозможное.

При доступном Mac отправлять не чаще раза в 15 секунд для обычного движения позиции, немедленно пытаться отправить явную паузу/переход и при подключении/выходе на передний план. Сначала устойчивая локальная запись, затем сеть. Сетевой сбой не мешает аудио. Фоновая отправка происходит в доступных ОС окнах; сохранность не зависит от точного фонового таймера.

#### Продолжить на другом устройстве

- Если источник уже на паузе, цель запрашивает актуальную ревизию, применяет позицию и делает seek **до** начала звука. Однонаправленное продолжение после подтверждённого checkpoint не требует диалога выбора.
- Если источник доступен и играет, пользователь нажимает «Продолжить здесь». Источник через сервис плеера ставится на паузу, получает фактическую позицию и устойчиво сохраняет финальный checkpoint. После подтверждения цель делает seek и запускает локальное аудио. Идентификатор операции защищает от повторного запуска.
- Если источник недоступен/не подтвердил паузу, показать «Последняя сохранённая позиция …; Mac может продолжать играть» и предложить «Продолжить с сохранённого места». Не сообщать, что удалённое воспроизведение остановлено.
- Во время собственного активного воспроизведения приходящий чужой прогресс не перематывает плеер. Сохранить кандидат и показать ненавязчивое предложение только при реальном конфликте.
- Две независимые офлайн-сессии образуют конфликт ветвей. Нельзя выбирать `max(position)` или только более поздние часы. Показать устройство, главу и время каждого варианта, предложить «Продолжить с iPhone» / «Продолжить с Mac». Выбор создаёт событие разрешения и сохраняет обе истории.
- Намеренная перемотка назад — нормальное действие. Более поздний подтверждённый seek на 20:00 имеет приоритет над старой записью 45:00 в той же причинной цепочке.

#### Поведение Mac обязательно входит в работу

Обновление SQLite на Mac не перематывает уже запущенный mpv само по себе. Входящий прогресс хранить через общий repository, а явные команды pause/seek/handoff проводить через `pudge/audiobooks.py` с актуальной позицией живого плеера. Исправить все пути сохранения, чтобы старый callback Mac не перезаписал только что принятый checkpoint iPhone.

При следующем обычном Play на Mac использовать выбранную последнюю ревизию. Старый открытый экран не должен передавать в плеер сохранённую в UI устаревшую позицию. Если mpv недоступен или не подтвердил команду, возвращается понятная ошибка, а не ложное подтверждение handoff.

Маршруты `/api/v2/...` ниже — **новый протокол Pudge**, не существующие маршруты Jiten. Сохранять v1 companion до завершения миграции.

- [ ] При timeout не обещать остановку источника; дать явный переход по последнему сохранённому месту. Повтор операции не ставит на паузу уже новую независимую сессию: связывать команду с source session ID и ревизией.

## 5. Конкретные команды проверки

Python следует запускать тем интерпретатором, который определён в T00; пример для штатного окружения:

```bash
make test PYTHON=.venv-test/bin/python
make test-batches PYTHON=.venv-test/bin/python
make quality PYTHON=.venv-test/bin/python
swift test --package-path ios/PudgeCore
xcodebuild -list -project ios/Pudge.xcodeproj
xcodebuild -showdestinations -project ios/Pudge.xcodeproj -scheme Pudge
```

После выбора существующего simulator UDID из последней команды, а не выдуманного имени модели:

```bash
xcodebuild -project ios/Pudge.xcodeproj -scheme Pudge -destination "platform=iOS Simulator,id=$PUDGE_IOS_SIMULATOR_ID" -derivedDataPath /tmp/pudge-ios-derived build test
```

`scripts/test_ios.sh` обязан проверять наличие `PUDGE_IOS_SIMULATOR_ID`, scheme и SDK и завершаться ошибкой при отсутствии; запрещено превращать недоступную проверку в PASS. Device acceptance выполняется отдельно и фиксирует модель/iOS. Сборку для установки проверить Xcode с фактической signing configuration пользователя.

Для точечных Python-задач используются указанные `tests/test_*.py`; успешный точечный тест не заменяет общий набор перед выдачей патча.

## 6. Сквозные приёмочные сценарии

### P0. Главный сценарий — аудиокнига между Mac и телефоном

1. На Mac слушать до выбранного места и поставить на паузу.
2. Открыть «Настройки → Расширенные → iPhone», отсканировать QR камерой внутри Pudge на телефоне.
3. В появившейся библиотеке скачать книгу; увидеть «На обоих» и «Доступно без сети».
4. Выключить Mac, продолжить на телефоне с того же места, заблокировать экран и слушать ещё 20 минут; сохранить закладку.
5. Вернуть связь, дождаться «Позиция синхронизирована»; на Mac нажать Play и продолжить с телефона, включая добавленную закладку.
6. На телефоне нажать «Освободить место»: удалить только локальное аудио после подтверждения Mac. Карточка становится «На Mac», а прогресс и закладка остаются.
7. Скачать обратно и убедиться, что продолжение, главы и закладки не сброшены.

Надпись «Позиция синхронизирована» появляется после receipt именно текущей checkpoint revision. Успешное подключение или отправка HTTP-запроса сами по себе её не включают.

### A. Уйти из дома с контентом

1. Подключить телефон к Mac, выбрать книгу с аудио и эпизод.
2. Скачать выбранные компоненты; увидеть проверенную готовность и размер.
3. Выключить Mac и сеть телефона; перезапустить Pudge.
4. Читать/слушать/смотреть, нажимать подготовленные слова, сохранять прогресс.
5. Подключиться обратно; не потерять действия и не получить двойную статистику.

### B. Освободить телефон

1. Один файл уже есть на Mac, второй импортирован только на iPhone, третий закреплён.
2. Нажать «Освободить место»: первый удаляется локально после проверки; второй сначала архивируется; третий остаётся.
3. Разорвать соединение на разных стадиях; после повторного запуска не потерять единственный оригинал.
4. Скачать обратно и сверить байты, закладки, исправления и прогресс.

### C. Ответы с двух устройств

1. A — ответ на Mac в 10:00; B — реальный ответ на iPhone в 11:00.
2. Доставить B раньше A; сохранить два события, не подменять времена временем доставки.
3. Исправить оценку A; добавить внешний C на сайте Jiten между preview и применением.
4. Полный режим: revision conflict → новая сверка → атомарная коррекция с сохранением C.
5. Ограниченный режим: показать block/plan; не выполнять разрушительную цепочку undo/replay и не заявлять, что Jiten исправлен.

### D. Субтитры как учебный интерфейс

1. Смотреть скачанную серию, нажать слово с фуриганой.
2. Увидеть правильное чтение/значение и текущий либо явно кешированный статус Jiten.
3. Добавить слово или открыть review, ответить ровно один раз.
4. Закрыть панель и продолжить с прежней позиции. При потерянном ответе сервиса увидеть «Проверяем результат», не повторять мутацию автоматически.

## 7. Что считать завершением

**Первый приоритет пользователя выполнен:** T16C и сценарий P0 пройдены на Mac + физическом iPhone. QR виден в расширенных настройках, аудио работает самостоятельно, позиция корректно передаётся в обе стороны, память освобождается без потери данных. Это отдельная полезная поставка; отсутствие Jiten и видео в ней не является основанием задерживать её.

**Готовая файловая часть:** R1, независимое использование контента и безопасная очистка пройдены на устройстве.

**Готовый повседневный iPhone Pudge:** контентные сценарии и интерактивные субтитры работают, Jiten имеет честно обозначенный режим, все обязательные проверки выполнены либо конкретно перечислены как недоступные.

**Полностью выполненный запрос о Jiten:** T14 пройден на целевом сервисе с сохранением чужих ответов и исходных времён. Локальный журнал, один отправитель и красивый экран конфликта по отдельности не выполняют это требование.

Исполнителю запрещено закрывать задачу формулировкой «история пересобирается», если изменяется только локальная база или карточка создаётся заново с потерей старых данных.
